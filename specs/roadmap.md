## 0. 使用说明

### 0.1 拆分原则

1. **每阶段可独立验证**：阶段结束时必须存在一个可运行的产物（Demo 窗口、可测模块或可见交互），不以「代码写完了」作为完成标准。
2. **每阶段有明确验收条件**：验收标准必须是可观测、可复现的事实描述，而非主观判断。
3. **技术前提前置**：高不确定性的技术验证（桌面层嵌入、全局钩子、分层窗口）安排在最前，避免后期返工。
4. **纵向切片优先**：每个阶段尽量贯穿「数据 → 逻辑 → 界面 → 可见效果」，而非横向铺完所有界面再做逻辑。

### 0.2 阶段状态标记

| 标记 | 含义 |
|---|---|
| ⬜ | 未开始 |
| 🟨 | 进行中 |
| ✅ | 已完成（验收通过） |
| ⛔ | 被阻塞 |

## 阶段 0 · 项目脚手架与工程规范 ✅

**目标**：建立一个可构建、可测试、可提交的空白工程骨架，使后续所有阶段有统一落点。

**关键任务**
1. 创建解决方案结构：`src/qDesktop.App`（WPF 宿主）、`src/qDesktop.Core`（数据模型与业务逻辑，无 UI 依赖）、`src/qDesktop.Interop`（全部 P/Invoke）、`tests/qDesktop.Core.Tests`。
2. 配置 `net8.0-windows`、`UseWPF`、`AllowUnsafeBlocks`、`UseWindowsForms`（托盘图标用）；运行时标识符固定为 `win-x64`（首版唯一目标平台，不配置 x86 / arm64）。
3. 接入 `Microsoft.Extensions.Hosting` 作为应用宿主，完成 DI 容器与配置装配。
4. 接入 Serilog 文件日志，输出到 `%APPDATA%\qDesktop\logs\`。
5. 添加 `.editorconfig`、`.gitignore`、`Directory.Build.props`（统一版本号与警告级别）。
6. 建立 GitHub Actions 工作流：`restore → build → test → dotnet format --verify-no-changes`。

**交付物**：可运行的空白 WPF 应用 + 绿色 CI 流水线。

**验收标准**
- `dotnet build` 零警告零错误（`TreatWarningsAsErrors=true`）。
- 应用启动后显示一个空窗口，日志文件正常写入。
- CI 在 PR 上成功执行并通过格式校验。
- 四个项目之间的引用方向正确：`App → Core`、`App → Interop`、`Core` 不引用 `Interop` 与任何 WPF 程序集。
- 构建产物为 `win-x64`，解决方案中不存在 x86 / arm64 目标配置；应用可在 Windows 10 1903+ 与 Windows 11 上启动。

**依赖**：无
**预估**：1 天

## 阶段 1 · 无边框透明窗口骨架 ⬜

**目标**：验证「分层 + 无边框 + 置顶 + 可穿透」窗口能否稳定共存——这是栅栏渲染与边缘隐藏的物理基础。

**关键任务**
1. 实现 `LayeredWindowHost`：`WindowStyle=None`、`AllowsTransparency=true`、`Topmost=true`、`ShowInTaskbar=false`。
2. 通过 `SetWindowLongPtr` 追加 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_LAYERED`。
3. 实现点击穿透开关：动态增删 `WS_EX_TRANSPARENT`，并提供 `IsClickThrough` 属性。
4. 实现窗口防激活：拦截 `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`。
5. 编写一个手动验证 Demo 页：三个按钮切换穿透、置顶、可见性。

**交付物**：`LayeredWindowHost` 控件 + 手动验证 Demo。

**验收标准**
- 窗口显示为无边框、无任务栏按钮、始终置顶。
- 开启穿透后，鼠标点击直接落到下层窗口；关闭穿透后可正常点击本窗口。
- 显示窗口时任务栏中其他窗口不失焦、不闪烁。
- 在 Win10 与 Win11 上行为一致。

**依赖**：阶段 0
**预估**：2 天

## 阶段 2 · 桌面层定位与图标数据源探测 ⬜

**目标**：确定「栅栏画在桌面之上、图标之下/之上」的准确层级方案，并确定不侵入桌面进程的图标读取路径。**这是全项目最大的技术不确定点。**

**关键任务**
1. 编写 `DesktopWindowProbe`：枚举 `Progman` 与 `WorkerW`，记录每种 Windows 版本下的实际窗口树结构。
2. 实现 `SendMessageTimeout(Progman, 0x052C, ...)` 触发 WorkerW 生成的兼容路径。
3. 实现 `IDesktopHostAdapter` 接口与 `WorkerWAdapter` 实现：把本程序窗口挂为 WorkerW 的子窗口。
4. 实现降级实现 `TopmostAdapter`：不嵌入桌面层，仅作为置顶窗口存在。
5. 读取桌面图标来源：通过 `SHGetKnownFolderPath(FOLDERID_Desktop)` + 公开桌面文件夹枚举，获取图标名称、路径、图标位图；**不采用**跨进程 `LVM_GETITEM` 内存注入方案。
6. 输出一份探测报告：Win10 / Win11 下的窗口树、可行方案、限制与风险。

**交付物**：`qDesktop.Interop` 中的适配层 + `docs/desktop-layer-probe.md` 探测报告。

**验收标准**
- 在 Win10 与 Win11 上均能定位到桌面图标宿主窗口，报告中记录实际句柄层级。
- 本程序窗口成功挂入 WorkerW 后，切换「显示桌面」时窗口不消失、Z 序正确。
- 能正确枚举桌面图标，返回的名称与路径与资源管理器一致（对比 ≥ 50 个图标的抽样）。
- 降级路径（`TopmostAdapter`）可用，且切换适配器不需要修改上层代码。

**依赖**：阶段 1
**预估**：3 天
**风险**：⛔ 若两种适配器均无法稳定工作，须回到 `tech-stack.md` 第 4 节重新评估，并可能下调边缘隐藏的产品预期。

## 阶段 3 · 数据模型与布局持久化 ⬜

**目标**：定义栅栏的领域模型与版本化持久化格式，这是所有后续功能的地基。**本阶段完全在 `qDesktop.Core` 内完成，无 UI。**

**关键任务**
1. 定义 `Fence` 领域模型：`Id`、`Title`、`Bounds`、`ZIndex`、`Type`（Container / Note / FolderMap）、`ParentId`、`Children`、`IsCollapsed`、`EdgeDock`、`Appearance`。
2. 定义 `LayoutDocument`：`SchemaVersion` + 根节点集合 + 全局设置引用。
3. 实现栅栏树的增删改查与**层级运算**：`GetDescendants`、`MoveTo`（含环检测，禁止把父节点移入自己的子孙）、`GetDepth`、`GetPath`。
4. 实现 `System.Text.Json` 序列化/反序列化，含自定义 `Converter` 处理 `ParentId` 与 `Children` 的一致性。
5. 实现原子写入：先写临时文件 → `File.Replace` 覆盖 → 保留 `layout.json.bak`。
6. 实现 `SchemaVersion` 迁移框架（当前仅 v1，但预留 `IMigration` 链）。
7. 编写单元测试：层级运算、环检测、序列化往返、损坏文件容错恢复。

**交付物**：`qDesktop.Core` 模型与持久化模块 + 完整单元测试。

**验收标准**
- 单元测试全部通过，`qDesktop.Core` 行覆盖率 ≥ 60%。
- 序列化 → 反序列化往返后，栅栏树结构完全一致（深度嵌套 ≥ 5 层场景验证）。
- `MoveTo` 把父节点移入自身子孙时抛出明确异常且不修改状态。
- `layout.json` 被手工破坏后，程序能回退到 `.bak` 并给出日志警告，不崩溃。
- `qDesktop.Core` 不引用任何 WPF 或 Interop 程序集。

**依赖**：阶段 0
**预估**：2 天

## 阶段 4 · 单个栅栏的可视渲染 ⬜

**目标**：让一个栅栏「看起来像栅栏」——半透明背景、标题栏、圆角、阴影、可配置外观。

**关键任务**
1. 实现 `FenceView` 用户控件：背景层（半透明填充 + 圆角）、标题栏（标题文本 + 按钮占位）、内容区。
2. 建立自建主题系统：`Theme.xaml` 定义颜色、圆角半径、透明度、字号等设计令牌（Design Token）。
3. 实现 `FenceViewModel`，绑定 `Title`、`Bounds`、`Appearance`。
4. 从 `layout.json` 加载栅栏并渲染到桌面宿主窗口上（位置取自 `Bounds`）。
5. 实现标题栏文本编辑（双击进入编辑态，失焦提交）。

**交付物**：可在桌面上看到一个可配置外观的栅栏。

**验收标准**
- 栅栏正确渲染在 `Bounds` 指定位置，圆角与半透明效果符合设计令牌。
- 修改 `Appearance` 中的颜色/透明度，栅栏外观实时更新。
- 双击标题可编辑并提交，修改后 `layout.json` 被更新。
- 栅栏不响应系统主题切换导致的异常重绘。

**依赖**：阶段 2、阶段 3
**预估**：2 天

## 阶段 5 · 栅栏的创建、移动与缩放 ⬜

**目标**：让用户能通过鼠标自由创建和调整栅栏。

**关键任务**
1. 实现桌面空白区右键菜单 → 「新建栅栏」，在鼠标位置创建默认尺寸栅栏。
2. 实现标题栏拖拽移动（含拖动时的实时预览，不做半透明拖影）。
3. 实现八向缩放边框与最小尺寸约束（如 120 × 80）。
4. 实现吸附：拖动时吸附到屏幕边缘与其他栅栏边缘（阈值 8 px），并显示吸附辅助线。
5. 实现 Z 序管理：点击栅栏置顶，持久化 `ZIndex`。
6. 移动/缩放结束后防抖写入 `layout.json`（防抖 500 ms）。

**交付物**：可交互的栅栏创建与布局调整能力。

**验收标准**
- 右键可创建栅栏，创建后立即可拖动。
- 拖动与缩放流畅，无可感知卡顿（≥ 55 FPS）。
- 吸附在屏幕边缘与其他栅栏边缘均生效，辅助线正确显示。
- 连续拖动 20 次后，`layout.json` 写入次数显著少于拖动次数（防抖生效），且最终位置准确。
- 缩放不小于最小尺寸。

**依赖**：阶段 4
**预估**：3 天

## 阶段 6 · 桌面图标渲染与图标缓存 ⬜

**目标**：把桌面图标以可控的方式绘制进栅栏，并解决图标提取的性能问题。

**关键任务**
1. 实现 `IIconProvider`：从 Shell 获取图标位图，转换为 WPF `BitmapSource`（处理 DPI 缩放）。
2. 实现磁盘缓存：以「文件路径 + 修改时间 + 尺寸」为键，缓存 PNG 到 `%APPDATA%\qDesktop\cache\icons\`。
3. 实现内存 LRU 缓存，限制条目数（如 500）。
4. 实现 `IconItemView`：图标 + 名称文本，支持选中态、悬停态。
5. 实现图标布局算法：网格排列（可配置每行列数或按栅栏宽度自适应）。
6. 实现名称过长截断 + 悬停显示完整名称（Tooltip）。
7. 性能基线测量：200 个图标场景下的首次提取耗时与二次启动耗时。

**交付物**：图标提取与缓存模块 + 栅栏内图标网格渲染。

**验收标准**
- 栅栏内正确显示桌面图标，图标清晰度在 100% / 150% / 200% DPI 下均正常。
- 首次加载 200 个图标耗时记录在案；二次启动（命中缓存）耗时 ≤ 首次的 30%。
- 图标名称过长时正确截断，悬停显示完整名称。
- 连续切换栅栏 50 次后，内存无持续增长（无 GDI/位图句柄泄漏）。

**依赖**：阶段 2、阶段 4
**预估**：3 天

## 阶段 7 · 图标归属与拖拽移入移出 ⬜

**目标**：让用户能把桌面图标拖入栅栏，并把归属关系持久化。

**关键任务**
1. 定义归属模型：栅栏持有图标引用（文件路径），而非移动真实文件——**默认不移动文件位置**。
2. 实现从桌面/资源管理器拖入栅栏的拖放处理（`IDropTarget` / WPF `AllowDrop`）。
3. 实现栅栏之间、栅栏内子区域之间的图标拖动重排。
4. 实现把图标拖出栅栏（拖到桌面空白区）→ 移除归属关系。
5. 处理冲突：同一图标被拖入多个栅栏时的策略（默认移动归属，不复制）。
6. 实现图标右键菜单：打开、打开所在位置、从栅栏移除、重命名（映射到真实文件重命名）。
7. 归属关系持久化并纳入单元测试。

**交付物**：图标归属与拖拽交互完整链路。

**验收标准**
- 从桌面拖图标入栅栏后，图标出现在栅栏内且归属被写入 `layout.json`。
- 重启程序后归属关系完全恢复。
- 把图标从 A 栅栏拖到 B 栅栏后，A 中不再显示该图标。
- 把图标拖出栅栏到桌面空白区后，归属被移除。
- 拖入不存在的文件路径时，图标显示为「失效」状态而非崩溃。

**依赖**：阶段 5、阶段 6
**预估**：3 天

## 阶段 8 · 自由层级（栅栏嵌套 / 分组树） ⬜

**目标**：实现核心差异化能力之一——栅栏可嵌套，层级深度不受限制。

**关键任务**
1. 实现把栅栏 A 拖入栅栏 B 内部 → 建立父子关系（复用阶段 3 的 `MoveTo` 与环检测）。
2. 实现嵌套栅栏的递归渲染：子栅栏在父栅栏内容区内相对定位。
3. 实现折叠 / 展开：折叠时只显示标题栏与子项计数。
4. 实现「面包屑 / 层级路径」显示，避免深层嵌套后迷失位置。
5. 实现把子栅栏拖出到桌面 → 提升为顶层栅栏。
6. 实现层级深度视觉区分（子栅栏背景色阶或内边距递增）。
7. 实现嵌套场景的坐标换算（父 → 子 → 桌面坐标互转）并纳入单元测试。

**交付物**：可任意嵌套的栅栏树。

**验收标准**
- 支持至少 5 层嵌套，渲染与交互均正常。
- 拖动父栅栏时，所有子栅栏跟随移动且相对位置不变。
- 折叠父栅栏后子栅栏隐藏，展开后恢复原状态。
- 无法把父栅栏拖入自己的子孙栅栏（UI 层面阻止并给出提示）。
- 重启后嵌套结构与折叠状态完全恢复。
- 坐标换算单元测试覆盖父/子/桌面三级互转。

**依赖**：阶段 7
**预估**：3 天

## 阶段 9 · 栅栏隐藏与显示切换 ⬜

**目标**：实现基础的手动隐藏 / 显示，为阶段 10 的自动边缘隐藏提供状态基础。

**关键任务**
1. 实现栅栏级显示/隐藏状态（`IsVisible`），并持久化。
2. 实现整体级显示/隐藏：一键隐藏全部栅栏，再次切换恢复。
3. 实现托盘图标与菜单：**左键单击托盘图标切换全部栅栏的唤起 / 隐藏**，右键弹出菜单（显示/隐藏全部栅栏、打开设置、导出诊断日志、退出程序）；单击切换与右键菜单互不干扰。
4. 实现全局热键（默认如 `Ctrl+Alt+D`）切换全部栅栏可见性。
5. 实现「隐藏时不占位」语义：隐藏的栅栏不响应任何鼠标事件。
6. 处理边界：全部隐藏后仍能通过托盘与热键恢复（防止用户把自己锁死）。

**交付物**：完整的显示/隐藏控制链路。

**验收标准**
- 单个栅栏可独立隐藏与显示，状态在重启后保持。
- 全局热键与托盘菜单均能切换全部栅栏，隐藏的栅栏不拦截鼠标点击。
- 全部隐藏状态下，托盘菜单与热键仍可恢复显示。
- **单击托盘图标**即可在唤起 / 隐藏全部栅栏之间切换，响应 ≤ 200 ms，托盘图标状态与栅栏实际可见性一致。
- 左键单击不弹出菜单，右键不触发切换；连续快速单击 20 次后，最终可见性状态与单击次数奇偶一致（无状态错乱）。
- 关闭主窗口时程序不退出，仅隐藏到托盘。

**依赖**：阶段 8
**预估**：2 天

## 阶段 10 · 边缘隐藏：触发检测 ⬜

**目标**：实现边缘隐藏的**判定逻辑**——检测鼠标是否进入/离开栅栏贴边区域的触发带。这是本项目核心差异化能力的技术核心。

**关键任务**
1. 定义 `EdgeDock` 模型：`Edge`（Top/Bottom/Left/Right）、`TriggerThickness`（默认 4 px）、`RevealDelay`、`HideDelay`、`AutoHide`。
2. 实现底层鼠标钩子 `WH_MOUSE_LL`，回调内**只**做坐标采样与入队，绝不做布局或 IO 操作。
3. 实现独立的判定线程：从队列消费鼠标坐标，计算是否进入触发带（区分显示器，含负坐标屏）。
4. 实现 `EdgeTriggerService`：发出 `RevealRequested` / `HideRequested` 事件，含可配置的进入/离开延迟防抖。
5. 实现钩子健康检查：检测钩子被系统摘除（超时）并自动重装。
6. 实现无钩子降级：钩子不可用时退化为「鼠标在窗口边缘区域时轮询」（`GetCursorPos` 定时采样）。

**交付物**：`EdgeTriggerService` + 钩子实现 + 降级路径。

**验收标准**
- 鼠标进入贴边触发带时，`RevealRequested` 在 ≤ 150 ms 内触发（100 次采样计时验证）。
- 鼠标离开后按 `HideDelay` 触发 `HideRequested`。
- 连续快速划过边缘 200 次，事件计数正确、无丢失、无重复。
- 程序空闲时（鼠标静止），钩子线程 CPU 占用接近 0。
- 人为破坏钩子（如模拟超时）后，服务能自动重装并记录日志。
- 多显示器含负坐标屏场景下判定正确。

**依赖**：阶段 9
**预估**：3 天
**风险**：⛔ 若底层钩子在目标环境下不稳定，须启用降级路径并同步更新 `mission.md` 第 6.1 节的性能标准。

## 阶段 11 · 边缘隐藏：动画与状态机 ⬜

**目标**：把触发事件转化为平滑的滑出/收起动画，并处理各种交互冲突。

**关键任务**
1. 实现 `EdgeDockStateMachine`：`Hidden → Revealing → Shown → Hiding → Hidden`，含中断与反向处理。
2. 实现滑出/收起动画：位移插值 + 淡入淡出，时长可配置（默认 180 ms）。
3. 处理「动画中反向触发」：滑出未完成时鼠标离开，应从当前位置平滑反向，不跳变。
4. 处理「显示中鼠标移入栅栏内部」：保持显示，不触发收起。
5. 处理「显示中栅栏被拖动」：自动解除边缘停靠或保持停靠后重算贴边位置。
6. 实现动画帧率优化：使用 `CompositionTarget.Rendering` 手动插值，避免大量 `Storyboard` 实例。
7. 实现性能降级：低配环境下自动缩短时长或改为无动画直接切换。

**交付物**：完整的边缘隐藏交互。

**验收标准**
- 鼠标划入边缘 → 栅栏平滑滑出；划出 → 平滑收起，动画无跳变、无闪烁。
- 滑出动画进行中反向划出，栅栏从当前位置平滑收回。
- 栅栏完全显示后鼠标移入栅栏区域，栅栏保持显示。
- 动画期间帧率 ≥ 55 FPS（60 Hz 显示器实测）。
- 快速连续划入划出 50 次，最终状态与鼠标位置一致，无卡死。
- 配置「关闭动画」后，切换为即时显示/隐藏。

**依赖**：阶段 10
**预估**：3 天

## 阶段 12 · 便签栅栏类型 ⬜

**目标**：在既有栅栏模型上落地第二种语义——便签。

**关键任务**
1. 扩展 `Fence.Type = Note`：内容区渲染为文本编辑器而非图标网格。
2. 实现便签文本编辑：多行输入、自动换行、失焦保存。
3. 存储策略：正文存为独立 `.txt` 文件于 `%APPDATA%\qDesktop\notes\`，`layout.json` 仅存路径引用。
4. 实现便签外观：纸张色、字体、字号可配置。
5. 实现便签的自动保存（防抖 800 ms）与崩溃恢复（对比临时草稿）。
6. 实现便签与普通栅栏的互相转换（转换时给出内容处置提示）。
7. 便签同样支持阶段 8 的嵌套与阶段 10 的边缘隐藏。

**交付物**：可用的便签栅栏。

**验收标准**
- 可创建便签、输入多行文本、失焦后自动保存。
- 重启程序后便签内容与外观完全恢复。
- 便签文件可用外部编辑器（如记事本）直接打开编辑，重新聚焦后内容被重新加载。
- 便签支持嵌套与边缘隐藏，行为与普通栅栏一致。
- 强制结束进程后重启，未保存内容可从草稿恢复或给出明确提示。

**依赖**：阶段 8、阶段 11
**预估**：2 天

## 阶段 13 · 文件夹映射栅栏类型 ⬜

**目标**：落地第三种语义——栅栏绑定真实文件夹并实时同步。

**关键任务**
1. 扩展 `Fence.Type = FolderMap`：持有 `SourcePath`，内容区展示该文件夹内容。
2. 实现文件夹内容读取：文件与子文件夹分开排序（目录优先，按名称/时间可选）。
3. 实现 `FileSystemWatcher` 监听：新增、删除、重命名、修改事件合并防抖（500 ms）后刷新视图。
4. 实现监听失效兜底：`FileSystemWatcher` 缓冲区溢出或网络路径不可靠时，降级为定时轮询（如 30 s）。
5. 实现源文件夹失效处理：路径不存在/无权限时显示明确错误态，保留栅栏结构不丢失。
6. 实现双向交互：栅栏内右键可新建文件夹/重命名/删除（需二次确认），操作直接作用于真实文件系统。
7. 实现「打开源文件夹」快捷入口。

**交付物**：文件夹映射栅栏完整功能。

**验收标准**
- 绑定文件夹后正确展示其内容，目录优先排序。
- 在资源管理器中新建文件，栅栏内 ≤ 2 s 自动出现该文件。
- 在资源管理器中删除文件，栅栏内对应项 ≤ 2 s 消失。
- 源文件夹被重命名或删除后，栅栏显示错误态且不崩溃，恢复路径后自动恢复。
- 在栅栏内删除文件时出现二次确认，取消后文件未被删除。
- 绑定一个含 500 个文件的文件夹，视图加载与滚动流畅。

**依赖**：阶段 8、阶段 11
**预估**：3 天

## 阶段 14 · 多显示器与 DPI 适配 ⬜

**目标**：保证在任意显示器组合与缩放比例下，栅栏坐标、尺寸、边缘触发均正确。

**关键任务**
1. 设置进程 DPI 感知模式为 `Per-Monitor V2`。
2. 实现显示器枚举与虚拟桌面坐标系（含负坐标屏、主副屏不同缩放）。
3. 实现跨屏拖动：栅栏从一个显示器拖到另一个时，尺寸按目标 DPI 正确换算。
4. 实现显示器热插拔响应：`WM_DISPLAYCHANGE` 后重新校验并修正越界的栅栏位置。
5. 实现边缘隐藏在多屏下的判定：仅对栅栏实际停靠的显示器边缘生效。
6. 实现「显示器断开后栅栏越界修复」策略：移回主屏并记录日志。
7. 建立测试矩阵并逐项手工验证：单屏 100% / 150% / 200%，双屏同缩放，双屏异缩放，负坐标副屏。

**交付物**：多屏与 DPI 正确性。

**验收标准**
- 测试矩阵全部通过，栅栏在各组合下位置与尺寸视觉正确。
- 跨屏拖动后栅栏尺寸随目标 DPI 正确换算，无模糊或错位。
- 拔掉显示器后，原在其上的栅栏自动移回主屏可见区域。
- 边缘隐藏在双屏异缩放场景下触发带位置正确（不出现触发带偏移到错误屏幕）。
- 100% / 150% / 200% 下图标清晰度均正常。

**依赖**：阶段 13
**预估**：3 天

## 阶段 15 · 设置面板与外观定制 ⬜

**目标**：把散落在各处的配置项集中到统一的设置界面。

**关键任务**
1. 实现设置窗口（普通窗口，非分层窗口），分页：常规、外观、边缘隐藏、栅栏默认值、高级。
2. 常规：开机自启、单实例、语言（首版仅中文）、日志级别。
3. 外观：**栅栏背景透明度（0–100% 连续可调）**、背景色、边框色、标题栏颜色、文本颜色、圆角半径、字号、图标大小、网格列数；支持「全局默认 + 单栅栏覆盖」两级配置。
4. 边缘隐藏：触发带厚度、显示/隐藏延迟、动画时长、动画开关。
5. 栅栏默认值：新建栅栏的默认尺寸、默认标题、默认外观。
6. 高级：布局文件路径（含「打开所在目录」）、导出/导入布局、重置全部布局（二次确认）。
7. 配置项与 `layout.json` / 应用配置双向绑定，即时生效并持久化。
8. 实现颜色与透明度编辑控件：颜色选择器（取色器 + 最近使用色 + 十六进制输入）、透明度滑块，并提供若干外观预设。
9. 实现外观实时预览：调整时栅栏即时反映，取消则回滚到调整前状态。

**交付物**：完整设置面板。

**验收标准**
- 所有设置项修改后即时生效，重启后保持。
- 导出布局生成可读 JSON，导入后栅栏树完全一致。
- 「重置全部布局」需二次确认，取消后数据未变。
- 开机自启开关正确写入/移除注册表项。
- 栅栏背景透明度可在 0–100% 间连续调节，调整时栅栏即时反映，重启后保持。
- 背景色、边框色、标题色、文本色均可自定义，支持取色器与十六进制输入。
- 单个栅栏可覆盖全局默认外观；重置后回落到全局默认值。
- 设置窗口在多屏与高 DPI 下正常显示，不越界。

**依赖**：阶段 14
**预估**：3 天

## 阶段 16 · 性能优化与稳定性加固 ⬜

**目标**：达成 `mission.md` 第 6.1 节的性能标准，并消除长时运行下的资源泄漏。

**关键任务**
1. 建立性能基线测量脚本：启动耗时、空闲内存、空闲 CPU、200 图标首屏耗时、动画帧率。
2. 优化启动路径：延迟加载图标、异步初始化、避免 UI 线程阻塞。
3. 优化渲染：虚拟化图标列表、冻结 `Freezable` 资源、减少 `Visual` 层数。
4. 排查句柄泄漏：`BitmapSource`、图标句柄、窗口句柄、钩子句柄的释放审计。
5. 长时稳定性测试：连续运行 8 小时并周期性操作，记录内存曲线。
6. 崩溃兜底：全局异常处理 + 布局文件损坏自动恢复 + 崩溃时保留当前布局快照。
7. 处理桌面「显示桌面图标」被关闭的场景：给出明确提示而非静默失效。

**交付物**：性能达标版本 + 性能基线报告。

**验收标准**
- 空闲常驻内存 ≤ 150 MB，空闲 CPU ≤ 1%（测量方法记录在报告中）。
- 冷启动到栅栏可见 ≤ 1.5 s（200 图标场景，SSD）。
- 8 小时连续运行后内存增长 ≤ 10%，无句柄数持续上升。
- 人为触发异常后，程序不崩溃或能自动恢复，布局数据不丢失。
- 关闭系统「显示桌面图标」后，程序给出明确提示。

**依赖**：阶段 15
**预估**：3 天
