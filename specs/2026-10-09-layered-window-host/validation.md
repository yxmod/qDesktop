## 1. 验证总则

### 1.1 判定原则

1. **可观测**：每条验证必须产出可复现的事实（命令退出码、窗口行为、扩展样式位），禁止使用「看起来正常」「应该没问题」等主观描述。
2. **可复现**：验证步骤须在**干净的克隆**上可重复执行，不依赖开发者本机遗留状态。
3. **可证伪**：关键验证项须给出**反例**（故意破坏后应失败），以证明校验逻辑真实生效，而非恰好通过。
4. **双版本覆盖**：涉及系统行为的验证须在 Windows 10 1903+ 与 Windows 11 上分别执行（本阶段覆盖策略见 V6）。

### 1.2 验证分类

| 类型 | 执行方式 | 是否阻断合并 |
|---|---|---|
| **自动化验证**（V1） | CI 流水线自动执行 | ✅ 阻断 |
| **静态/结构验证**（V1） | 人工检查 + 仓库搜索 | ✅ 阻断 |
| **手工验证**（V2–V6、M1–M4） | 评审者本地执行并记录 | ✅ 阻断 |
| **文档一致性检查** | 人工比对 | ✅ 阻断 |

> 本阶段**不引入自动化行为测试**（依据 `requirements.md` 3.7 与 `tech-stack.md` 2.5）：窗口行为依赖真实桌面合成与输入路由，由人工验收清单覆盖。

### 1.3 验证环境基线

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 1903+ / Windows 11（覆盖策略见 V6） |
| 架构 | x64 |
| 桌面合成 | DWM 启用（默认） |
| 辅助工具 | Spy++ 或等效窗口样式查看工具（用于读取 `WS_EX_*` 位） |
| 仓库状态 | 干净克隆，无未提交改动 |

连续执行「切换穿透 → 切换置顶 → 切换可见性」循环 10 次，观察窗口响应。

- **通过判据**：每次切换均即时生效（无可感知延迟），窗口无闪烁、无残影。
- **说明**：阶段 1 **不设**帧率阈值（边缘隐藏动画的帧率要求属阶段 11），仅记录主观观感。

## 8. 阻塞与回退

### 8.1 阻塞判定

出现以下任一情况，本阶段标记为 ⛔ 被阻塞并暂停合并：

1. 「分层 + 无边框 + 置顶 + 穿透」四项属性无法在目标系统上稳定共存（须回到 `tech-stack.md` 第 4 节重新评估窗口方案）。
2. `WS_EX_NOACTIVATE` 导致窗口完全无法接收任何鼠标事件，且无法通过样式组合规避。
3. `qDesktop.App` 在不直接 `DllImport` 的前提下无法完成扩展样式操作（须回到 `requirements.md` 3.2 重新评估分层归属）。

### 8.2 回退策略

| 情况 | 回退动作 |
|---|---|
| 点击穿透在某些 Windows 版本上不稳定 | 保留 `IsClickThrough` 的 API 形态，记录受限版本与现象，交由阶段 4 决定是否改为「穿透由上层内容决定」；**不**降级为「无穿透」的替代方案（`mission.md` 6.3 反成功标准） |
| 双版本中另一版本不可达 | 按 V6.2 标注「待补」，随阶段 2 双系统探测补验；**不**视为本阶段未完成 |
| `Alt+Tab` 无法切回 Demo 窗口导致穿透无法关闭 | 借助可见性守护或先结束进程重开；将该现象记录为「验证操作限制」，不影响产品行为判定 |
| MVVM 绑定在无激活窗口下出现异常 | 优先保证窗口属性正确；绑定细节可简化，但**不**退回 code-behind 直接操作窗口属性（`requirements.md` 3.3 已决策） |

### A.3 与规格的偏差（如有，须回改文档）

> 以下三项均为**实现期人工试用后发现的缺陷**所导致的修正，已同步回改 `requirements.md`（3.5、3.6、D4）
> 与 `plan.md`（TG2.3、TG4.2、TG4.3、TG5.2）。

1. **`WM_MOUSEACTIVATE` 拦截中增加 Z 序提升**：`WS_EX_NOACTIVATE` 会一并抑制「点击激活 → 自动提升
   Z 序」的系统行为。原实现仅返回 `MA_NOACTIVATE`，导致**关闭置顶后窗口无法再被点击带到最前**。
   现于拦截时补发 `SetWindowPos(HWND_TOP, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)`，
   只提升、不激活（`requirements.md` 3.5）。
2. **三个切换项统一增加防锁死守护**：原实现仅对可见性设 3 秒守护。实测发现**开启穿透后窗口
   既不可点击、也无任务栏与 `Alt+Tab` 入口**，验证者被完全锁死。现将守护扩展为三项统一策略
   （穿透开启 10 秒 → 关闭；置顶关闭 10 秒 → 恢复；可见性隐藏 3 秒 → 恢复），并在状态文本中
   实时显示剩余秒数（`requirements.md` 3.6）。
3. **可见性改由视图在属性变更回调中应用，不再使用 XAML 绑定**：窗口根元素上的 `Visibility`
   绑定会被 `Window.Show()` 设定的本地值顶掉，绑定随之中断，表现为**点击「切换可见性」后窗口
   不消失**。原为此新增的 `BoolToHiddenVisibilityConverter` 与 `App.xaml` 中的资源注册一并移除
   （`plan.md` TG4.3、TG5.2）。
4. **`IsClickThrough` 采用依赖属性实现**：`plan.md` TG3.1 仅要求「新增 `IsClickThrough` 属性」，
   实现为 `DependencyProperty` 以同时满足双向绑定与变更通知，不改变对外语义。
5. **日志实现**：`ShowInTaskbar` 运行时切换的警告（`requirements.md` 3.4 / `plan.md` TG2.5）
   经 Serilog 静态日志器记录，与 `App.xaml.cs` 的既有日志方式一致。
